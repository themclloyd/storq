Flat collection of ordered SQL migration files under `supabase/migrations/`, driven by the Supabase CLI against project `gtkfczmudhzhbdooftsa` (declared in `config.toml`).

- Data model: multi-tenant retail schema rooted at `businesses`, then `stores`, `staff`, `staff_sessions`, `products`, `product_costs`, `store_stock`, `sales`, `sale_items`, `sale_item_costs`, `payments`, `refunds`, `refund_items`, `stock_takes` / `stock_take_lines`, `cash_shifts`, `cash_movements`, `expenses`, `collections`, `product_collections`, `subscriptions`, `subscription_payments`, plus `pin_throttle` for brute-force protection.
- Security boundary: RLS is enabled on every table; authenticated clients receive SELECT only, while all writes go through `SECURITY DEFINER` functions. The `public` schema exposes thin `public.*` wrappers defined with `SECURITY INVOKER` that delegate to real business logic in the `app.*` namespace defined with `SECURITY DEFINER SET search_path = public`. Internal helpers (`require_staff`, `require_staff_nosub`, `pin_taken`, `_move_stock`, `effective_price`, `subscription_active`, `session_role`, `set_ctx`) are revoked from `public, anon, authenticated` and granted only to `service_role`.
- Tenancy enforcement: `public.my_business_id()` resolves the current user's business from `auth.users`; the hardening migration adds `app.session_role()` bound to a device-scoped staff session (`staff_sessions.auth_uid = auth.uid()`) so money-sensitive reads require a verified PIN unlock.
- RPC surface: every client-facing mutation is a function taking a UUID staff token plus parameters; role checks are done inside `require_staff` against arrays like `['admin','manager','cashier']`. Business rules (PIN shape, price bounds, stock floors, plan limits) live in both CHECK constraints and PL/pgSQL validation.
- Migration ordering: initial schema + RLS in the first file, indexes in a dedicated index migration, security hardening in `20261008090000_security_hardening.sql` (which rewrites most `public.*` functions into `app.*`, moves cost columns to gated tables, adds PIN throttling and device-bound sessions), then feature migrations for retail operations, sales summaries, item codes, and fixes.
