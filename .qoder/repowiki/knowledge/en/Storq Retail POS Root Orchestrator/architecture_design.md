The root is a single TanStack Start (Vite + Nitro) application; `vite.config.ts` delegates plugin setup to `@lovable.dev/vite-tanstack-config` and only overrides the server entry (`src/server.ts`) plus pre-bundles heavy route-lazy libraries (`@supabase/supabase-js`, `jspdf`, `recharts`) and warms the router/routes/components graph for SSR. The `frontend_app` child consumes the Supabase JS client and maps its routes/data layer onto the `database_schema` child's PostgreSQL migrations, RLS policies, and stored procedures — there is no shared TypeScript package between them; the contract is the database schema itself. Environment variables are templated through `.env.example`, typed via `tsconfig.json`, and locked by Bun's lockfile with a 24-hour minimum release age policy enforced by `bunfig.toml`. Linting/formatting/test tooling (ESLint, Prettier, Vitest) is configured once at this level and inherited by both children.
