## System / Approach

The project uses **Bun** as its package manager for a single-workspace Node/TypeScript application built on TanStack Start.

- Dependency declarations live in `package.json` under `dependencies` (runtime) and `devDependencies` (tooling).
- The resolved, reproducible tree is pinned in `bun.lock` (lockfile version 1), which is committed to the repo.
- No vendored `node_modules`; dependencies are installed from registries at build time.
- There is no Go toolchain or Go modules present — this category applies only to the JS/TS side of the repo.

## Key Files

- `package.json` — declares all runtime and dev dependencies, plus an `overrides` block.
- `bun.lock` — deterministic lockfile generated by Bun; contains exact versions and SHA digests for every transitive dependency.
- `bunfig.toml` — Bun configuration controlling install behavior and supply-chain policy.
- `.gitignore` — ensures `node_modules/` is not tracked (so the lockfile is the source of truth).

## Architecture and Conventions

### Version ranges
Most packages use caret (`^`) ranges (e.g. `"react": "^19.2.0"`, `"@supabase/supabase-js": "^2.117.2"`). A subset of critical framework packages are pinned to exact versions:
- `"@tanstack/react-router": "1.170.41"`
- `"@tanstack/react-start": "1.168.60"`
- `"@tanstack/router-plugin": "1.168.42"`
- `"vite": "8.1.5"`
- `"nitro": "3.0.260603-beta"`
This pattern keeps the core framework stack locked while allowing minor/patch drift for other libraries.

### Dependency overrides
`package.json` contains an `overrides` block forcing `rolldown` to `1.2.1`. This override is mirrored in `bun.lock` under `overrides`, so it is enforced at resolution time.

### Private registry usage
Two packages (`@hugeicons/core-free-icons`, `@hugeicons/react`) resolve from a Google Artifact Registry mirror rather than the public npm registry:
```
https://europe-west4-npm.pkg.dev/lovable-core-prod/sandbox-npm-cache/@hugeicons/...
```
The URL is embedded directly in `bun.lock` tarball fields. No global `.npmrc` or Bun registry config was found in the repo root, so these URLs are likely configured via environment variables or a per-project Bun registry setting outside the committed files.

### Supply-chain guard
`bunfig.toml` enforces a 24-hour minimum release age for newly published packages:
```toml
[install]
saveTextLockfile = true
minimumReleaseAge = 86400
minimumReleaseAgeExcludes = ["@lovable.dev/vite-tanstack-config", "@lovable.dev/mcp-js", "@lovable.dev/email-js", "@lovable.dev/webhooks-js"]
```
- `saveTextLockfile = true` tells Bun to write the human-readable `bun.lock` text format (instead of a binary-only lockfile).
- `minimumReleaseAge = 86400` blocks installation of packages published less than one day ago.
- `minimumReleaseAgeExcludes` whitelists four `@lovable.dev/*` packages so they can bypass the 24h guard without prompting.

### Scripts
`package.json` exposes standard scripts (`dev`, `build`, `build:dev`, `preview`, `lint`, `format`, `test`, `test:watch`) but no dedicated script for auditing or upgrading dependencies (no `npm audit`, `bun upgrade`, etc.).

## Conventions and Constraints

- **Lockfile is authoritative**: `bun.lock` is committed and `node_modules/` is ignored; CI and local installs should derive the dependency tree from the lockfile.
- **Framework packages pinned exactly**: `@tanstack/*`, `vite`, and `nitro` use exact version strings in `package.json`, preventing accidental upgrades across major/minor boundaries.
- **Other packages use caret ranges**: non-critical dependencies allow patch-level updates automatically.
- **Rolldown forced via overrides**: the `overrides` entry for `rolldown` is enforced by both `package.json` and `bun.lock`.
- **New-package quarantine**: Bun's `minimumReleaseAge = 86400` prevents installing packages published within the last 24 hours unless explicitly excluded in `minimumReleaseAgeExcludes`.
- **Private packages come from a Google Artifact Registry mirror**: `@hugeicons/*` packages are fetched from `europe-west4-npm.pkg.dev/lovable-core-prod/sandbox-npm-cache/` as recorded in `bun.lock`.
- **No workspace monorepo structure**: `bun.lock` shows a single workspaces entry (`"": { name: "tanstack_start_ts" }`), confirming this is a flat single-package project.
